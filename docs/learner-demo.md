# Learner demo

Home offers **Add learner** when the supervisor has no learners, and shows every saved learner afterwards. The three-step wizard uses Location (Australia → Victoria), Learner details (name, date of birth, permit confirmation and demo agreement), then Confirm. The final screen shows the location, learner details and checked confirmations, offers Edit actions, and contains the Create learner button. State stays hidden until a country is chosen. The progress bar stays above the scrolling form at 33%, 67% and 100%.

## Run

For the full Mac setup, development-build installation, and repeatable iPhone 16 launch commands, see [Local development](local-development.md).

Use Node 24 LTS (or an Expo SDK 57 supported Node version).

```sh
npm install
npx supabase start
npx supabase status
```

Copy `.env.example` to `.env.local` and set:

```dotenv
EXPO_PUBLIC_SUPABASE_URL=http://127.0.0.1:55321
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<publishable key from supabase status>
```

For a physical phone, use the computer's LAN IP instead of `127.0.0.1`, keep both devices on the same network, and allow local network access. For the Android emulator, use `10.0.2.2`. After changing storage modes, stop Metro and restart with `--clear` so environment values are rebuilt. Edit `.env.local` itself when switching to local-only mode.

```sh
npx expo start --port 8091
```

The new native dependencies are included in the SDK's Expo Go distribution. An existing custom development build needs rebuilding to include them. Native projects continue to be generated by Expo; no hand-written iOS/Android projects are needed.

The local instance uses its own project ID and ports **55321** (API), **55322** (Postgres), and **55323** (Studio), keeping the pre-existing local Supabase project on ports 543xx separate. Only the public/publishable key belongs in the app. Studio: http://127.0.0.1:55323.

## Data and demo identity

- With both environment variables configured, learner creation writes to Supabase. A persistent anonymous Auth identity represents the demo supervisor until real account sign-in is built. Each installation/browser has its own identity; there is no shared hardcoded account.
- The learner row contains the owner ID, name, date of birth (`date`), AU/VIC location, the confirmed checklist, the checklist/agreement versions, and server-generated acceptance/creation timestamps.
- RLS and grants allow authenticated supervisors to read and insert only their own learners. Database constraints validate location, minimum age and confirmations. Updates, deletions and client-supplied timestamps are not exposed.
- A successfully read or created learner is cached by account ID in AsyncStorage. Cached learners can be displayed when a server read fails. Creation requires connectivity when Supabase is configured; no background sync queue is implemented.
- If both environment variables are blank, the same flow persists locally in AsyncStorage for a standalone demo. This mode has no server authentication. A partially configured Supabase connection is an error, not a switch to local mode.
- Local-only records do not automatically migrate when Supabase is enabled. Clearing the demo Auth session loses access to that anonymous identity's records; real account linking/recovery is future work.
- Stable creation IDs make retrying an uncertain save safe from duplicate inserts. Failed writes stay on the form. Successful server writes are not reported as failed just because the optional local cache is unavailable.
- Plans, paywalls and practice-session creation remain outside this change.

## Victorian requirements and agreement

Reviewed 23 September 2026 against current official sources:

- [Transport Victoria: learner and probationary driver rules](https://transport.vic.gov.au/road-and-active-transport/road-rules-and-safety/learner-and-probationary-driver-road-rules), also linked from [VicRoads: Driving on your Ls](https://www.vicroads.vic.gov.au/ls-and-ps/driving-on-your-ls).
- [Transport Victoria: eligibility for a learner permit](https://transport.vic.gov.au/road-and-active-transport/registration-and-licensing/licences/learner-permit/prepare-for-your-learner-permit): minimum age 16 for a car learner permit.

Learner creation confirms only possession of a valid learner permit. The other checks (L plates, supervision, safe driving, devices and towing) are retained in `src/features/practice/requirements.ts` for the future practice-session start flow; they are not marked accepted on new learner profiles. The Practice screen remains a placeholder until that flow is built. Requirements for graduating to a probationary licence (such as accumulated hours) are not prerequisites for creating a learner profile.

The user approved a short **demo agreement**. Its text is readable in a sheet before agreement. `demo-v1` and `vic-learner-2026-09-23-v2` are stored with new records. The follow-up migration preserves earlier `vic-car-2026-09-23` confirmations without changing their meaning; changes to the checklist or agreement should introduce a new version and corresponding migration.

## Checks

```sh
npm run lint
npx tsc --noEmit
npm test
npm run test:db
npx expo export --platform all --output-dir /tmp/karla-learner-export
```

`npm test` covers date validity, exact sixteenth-birthday boundaries, date-only handling, name/location validation, permit confirmation and terms. The database suite runs inside a rolled-back transaction and checks ownership isolation, restricted writes, server timestamps, age/location checks and confirmations.

Browser QA should exercise: the empty Home screen; hidden/reset state selection; Next gating; 33%/67%/100% progress; back navigation retaining data; underage/future birth dates; agreement sheet; Confirm-only creation; review Edit actions; creation gating; save/reload; multiple learners; failed-save retry; and account-scoped cached reads. Native bundle export validates imports but does not replace testing the native picker UI on a device.
