# Practice sessions

Practice recording is implemented for iPhone, with Apple Maps navigation. Android and web can display learner history and reviews; their Practice action explains that recording requires the iPhone app.

## Local configuration

Follow [local-development.md](local-development.md) to start the database, Metro, and iPhone 16 simulator. Add your **public** Mapbox token to the ignored `.env.local`:

```dotenv
MAPBOX_ACCESS_TOKEN=pk.your_public_token
```

`app.config.ts` exposes this public token through Expo `extra.mapboxAccessToken`. It rejects secret (`sk.`) tokens. Restart Metro after changing it. `EXPO_PUBLIC_MAPBOX_ACCESS_TOKEN` is also accepted as a fallback. For standalone/EAS releases, configure the same public token in the corresponding EAS environment; the ignored local file is not uploaded. Never place a secret Mapbox token or Supabase service-role key in this application.

The iPhone route preview uses native Apple Maps through the installed `react-native-maps` library, drawing the geometry and stop markers returned by Mapbox Directions. It needs no additional API key. Web uses a schematic preview. Android's native Google Maps view needs a Google Maps SDK key when building for Android.

Apply the practice migration without resetting existing data:

```sh
npx supabase migration up --local
```

The feature adds `expo-location`, `expo-task-manager`, `expo-notifications`, `expo-sqlite`, and `react-native-maps`. **A new development build is required.** Expo Go and the old Karla Drive simulator binary do not contain the required modules. `app.json` configures background location and permission messages; native directories remain generated by Expo.

```sh
npx eas-cli@latest build --platform ios --profile development-simulator
npx eas-cli@latest build:run --platform ios --profile development-simulator --simulator "iPhone 16"
```

## User flow

1. Practice is disabled until a learner exists. Tapping it checks precise foreground GPS, Always/background location, and notification alerts. Missing permissions use native prompts and explanatory popups. Any refusal leaves the user on the existing screen. Open Settings is offered when iOS cannot prompt again. Returning from Settings rechecks all permissions. iOS controls its Allow Once / While Using / Always choices; there is no separate generic background-task permission.
2. Practice opens a full-screen two-step wizard using the Create Learner progress bar, header, and back navigation. The selected learner appears under Supervising above four unchecked, title-only acknowledgements for the supervisor to confirm their own readiness, the car, and the learner. All four must be ticked to enable Next. Content scrolls independently of the fixed bottom action, above the safe area. Back from route settings preserves the checks; leaving the wizard resets them for the next drive. These checks are saved on the session.
3. Generate route defaults to 45 minutes, with 48 choices from 15 minutes to 12 hours. Mapbox Directions tries up to six loops, adjusts their size toward the requested duration, and snaps three intermediate stops to roads. A separate Generate Route button below Duration prepares the loop without recording or opening Maps. Success scrolls to a map preview with the loop and intermediate stops, followed by Route ready with the estimated time and distance. The fixed bottom Start in Apple Maps button stays disabled until generation succeeds; changing the duration or route mode clears the prepared route. Regenerating also clears the old route, so a failed or cancelled attempt cannot start it. Generation errors remain in the wizard for retry, and going back during generation cancels it without starting a session. Geography/road availability can prevent a suitable loop. The Start recording option shows only “Karla will start the practice session.” Its fixed bottom Start recording button begins recording and opens the ongoing practice screen directly, with no Apple Maps handoff.
4. Starting either mode durably creates the recording, starts the registered location task, posts a local notification, and replaces the wizard with the ongoing session. Start in Apple Maps also opens Maps for generated routes, passing the origin, ordered stops, and return destination using Apple's iOS 18.4+ directions links. Apple Maps chooses the roads and the user starts navigation there. Returning from Maps shows the ongoing session. Failed Maps launches leave a visible recording with the Stop control; the supervisor can open Apple Maps directly from iOS. Start recording retains the internal destination route mode for compatibility with existing saved sessions; history labels these sessions Practice recording.
5. The ongoing session uses a dedicated full-screen route outside the tabs, with no Home/Practice/Account navigation, close button, or back button. Swipe-to-dismiss and hardware Back are blocked until the session is stopped. Opening a link to another app screen or relaunching Karla with an active session restores the live screen. The ongoing screen fits within the safe area, with Stop at the bottom and no Practice in progress label or top-right Open Maps button. Supervisor tips sit above the live metrics without a divider between the two areas. The tips form a horizontal carousel showing only the coaching content, with no module title or status badge, plus swiping, previous/next controls, and a card counter. Cards advance every 10 seconds, pause while touched, and resume 15 seconds after the last interaction. Autoplay stops when the screen loses focus, the app enters the background, or Reduce Motion or a native screen reader is enabled; a single card stays still. Only the recorded learner’s modules marked Need practice or Not performed with nonblank coachingTip content appear. When none have actual tips, the entire Supervisor tips section is hidden and its space collapses, including while content is loading or unavailable. Module details retain their coaching-material placeholders. TODO: add module-specific coachingTip prompts to the catalogue; they support the supervisor and do not assess or directly coach the learner during the drive. The lower area shows elapsed time on the first row, current speed and distance side by side on the second row, and a green GPS acquired banner while a valid fix is less than 20 seconds old and tracking has no error. Missing or stale fixes show a light-gray Acquiring GPS banner with a spinner and hide stale speed. The centered red circular Stop control has a square icon and an accessible label; GPS gaps are no longer displayed on this screen. Stop seals the local record before stopping native location updates, so late callbacks cannot add to the session. Review opens afterward; closing, saving, or discarding the review returns Home. Setup and ongoing views both label the learner Supervising.
6. The results sheet shows elapsed and moving time separately, other metrics, activity counts, and the recorded trace. Module choices default to Need practice and Not performed, with Show all available. A supervisor explicitly changes assessments and saves the review. Review later retains the finished session. Discard asks for confirmation, removes the recording and events, and leaves module assessments unchanged. A saved review cannot subsequently be discarded through this flow.
7. The Home Practice sessions card opens learner-scoped history sorted by end time descending. Finished sessions contribute observed moving plus stopped time to the existing practice-hour display. Night time is estimated from solar elevation at recorded locations; GPS gaps are excluded. These are app estimates, not a replacement for a signed official logbook.

## Recording and detection

`src/features/practice/runtime.ts` registers the task at module scope, imported by the root provider. GPS samples store timestamp, latitude, longitude, horizontal accuracy, speed, heading, and altitude. SQLite transactions persist the samples before notification, map matching, or upload work.

- Samples worse than 50 m accuracy, duplicate/out-of-order timestamps, and jumps faster than 75 m/s are rejected.
- iPhone recording receives available fixes without a movement threshold or background batching delay, with automatic location pausing disabled. This keeps stationary fixes eligible for stopped time and the GPS banner; iOS chooses the actual delivery cadence. The Android-only `timeInterval` does not schedule iOS callbacks. Recovery updates any persisted task that still uses the old 3 m filter or batching delay. Poor reception can still leave GPS acquiring; stale readings are never extended into assumed stopped time.
- Intervals over 30 seconds are GPS gaps, not moving or stopped time. The trace shows breaks across these gaps. Late or missing GPS cannot invent mileage or hours.
- Sustained GPS speed transitions infer moving off and stopping. Hysteresis and a five-second dwell avoid repeated notifications at threshold noise.
- Mapbox Map Matching processes actual recorded points, up to 100 per request with overlapping windows. Only confident matches with approach/departure observations can suggest left/right turns, roundabouts, and possible merges. Deduplication prevents overlap from double counting.
- Planned maneuvers never count as performed. Lane changes, mirror checks, observation quality, parking quality, and other unobservable skills require supervisor assessment. A detected merge does not establish a lane change or competence.
- Notifications are silent local banners. Only newly detected activity within the previous minute generates a banner; recovered historical detections update the results without replaying old alerts. iOS Focus and notification settings may suppress presentation.
- Mapbox outages do not interrupt GPS persistence. Unmatched recordings retry when the app returns to the foreground; results label pending matching. Ending the session does not require network access.
- Force quitting, revoked permissions, or OS termination can interrupt delivery. Recovery preserves recorded data and exposes Resume/Stop when the native task is no longer running. Continuous recording after force quit is not promised.

## Persistence and sync

Native storage is `karla-practice-v1.db`, with session metadata, raw points, deduplicated events, and minimal discard tombstones. Only one local recording can be active. Finished records remain available offline and retry upload through the current supervisor's anonymous Supabase identity. Web caches downloaded history/reviews in AsyncStorage but does not record.

The migration creates `practice_sessions`, `practice_points`, `practice_events`, and `practice_discards`, with owner-only RLS reads and validated RPC writes. Composite learner/account foreign keys prevent attaching recordings to another supervisor's learner. Batches are idempotent; revision checks prevent old acknowledgements from marking newer local work uploaded. A discard deletes the raw recording and keeps only its opaque ID/ownership tombstone so delayed uploads cannot resurrect it. Server discards are also applied to local caches.

Review statuses are staged until Save session & review. The review RPC applies them once and checks the assessment timestamps captured at review time. Concurrent newer assessments are preserved and listed as conflicts in the saved session. Chained offline reviews can resolve timestamps through the preceding applied review. GPS detection never promotes module status automatically.

## Verification

```sh
npm run lint
npx tsc --noEmit
npm test
npx supabase test db
npx expo-doctor
npx expo export --platform web --output-dir /tmp/karla-web-check
```

Verified on 24 September 2026: 30 application tests, 56 database assertions, lint, type checking, Expo Doctor (21/21), and iOS/web exports pass. On iPhone 16 / iOS 18.5, native permission denial stayed on Home, granted permissions skipped to the checklist, a generated loop opened Apple Maps with three stops and a return destination, and a simulated background drive recorded 0.50 km and a turn. Stop/results, supervisor review sync, history, Pick destination, and discard were exercised. The temporary QA learner/recordings were removed afterward.

The two-step wizard was also verified on iPhone 16: fixed Next while scrolling the checklist, disabled Next until all checks pass, back navigation preserving checks, both route modes with fixed actions, separate generation without creating a recording, Start enabled only after generation and disabled again after a duration change, Maps handoff, return to the live session, Stop/results, and a fresh checklist for the next session. The full-screen active flow was verified without tabs or a Back button: an edge swipe and a Home deep link kept the active session visible, relaunch restored it, and Stop opened results with a working return to Home. Route ready appears below the map and setup/live learner labels read Supervising. Temporary QA data was removed and the original learner selection restored.

The automated suite covers classification/gaps, invalid and duplicate points, route links/selection, map-matching evidence, real SQLite persistence and acknowledgement races, discard tombstones, owner isolation, idempotent uploads, review conflicts, and database totals. Live Mapbox smoke checks use public Melbourne coordinates, never the device's private current location.

For simulator GPS:

```sh
xcrun simctl location "iPhone 16" set '-37.8136,144.9631'
# Restore the normal simulator location state when finished.
xcrun simctl location "iPhone 16" clear
```

Use Simulator Features > Location for a moving route. Check denial stays on Home; granting all permissions opens the checklist; Next remains disabled until checked; Generate route opens Maps; Start recording goes directly to the ongoing practice screen; Stop/results; Review later/history; Save review; Discard/history count; reload recovery and an offline recording.

A physical iPhone drive is still required to validate locked-screen delivery, real Apple Maps navigation, notification presentation under Focus, battery use, and maneuver accuracy on real roads. Simulator GPS and automated fixtures cannot establish those behaviors.
